# PRD: 小红书商品种草发布包生成器 MVP

## 1. 背景

短视频创作者和小商家需要持续生产内容，但现有工具要么偏剪辑，要么偏生成，缺少面向小红书 / 抖音 / 视频号的完整生产流水线。

真正痛点不是生成一个视频，而是稳定地产出符合平台风格、可复用、可批量测试的内容。

本 MVP 先从“小红书商品种草发布包”切入，用最窄场景验证：商家是否愿意用 AI 工作流批量生成可发布内容。

## 2. 目标用户

### 主要用户

小红书 / 抖音矩阵号运营者、小商家。

特征：

- 需要每天/每周持续产出内容。
- 有商品或服务素材，但缺脚本和内容角度。
- 会人工发布和微调，但不想每条从零开始写。

### 次要用户

- 本地生活商家
- 跨境电商卖家
- 知识付费团队
- MCN 小团队

## 3. 问题陈述

用户现在的工作流通常是：

```text
找商品/素材 -> 想标题 -> 写脚本 -> 找参考 -> 拆分镜 -> 剪映剪辑 -> 写发布文案 -> 发布 -> 用表格记录数据
```

问题：

- 标题和脚本生产慢。
- 同一个商品很难批量生成不同角度。
- 不知道哪些标题、hook、封面、脚本结构有效。
- 素材和脚本版本管理混乱。
- 平台风格不匹配，通用 AI 文案很难直接用。

## 4. 产品目标

### 用户目标

让用户输入一个商品后，快速拿到可人工修改、可发布、可测试的短视频发布包。

### 业务目标

验证小商家是否愿意为“批量短视频发布包 + A/B 测试管理”付费。

### 技术目标

建立本地 Go 后端 + workflow 节点 + 后续 tRPC-Agent-Go 接入的产品骨架。

## 5. 非目标

MVP 不做：

- 完整视频剪辑器
- 自动登录和发布到小红书
- 自动抓淘宝/1688 完整详情页
- 自动抓平台数据
- 多平台同时覆盖
- 全自动高质量成片
- 团队权限系统
- 云端计费系统

## 6. 核心用户旅程

1. 用户打开本地 Web 控制台。
2. 点击“新建项目”。
3. 选择模板：小红书商品种草。
4. 填写商品信息：标题、链接、价格、卖点、目标人群、素材目录。
5. 点击“生成发布包”。
6. 系统生成商品分析、标题、封面、脚本、分镜、素材计划、发布正文。
7. 用户人工编辑脚本或标题。
8. 用户点击“生成 10 个变体”。
9. 系统生成多个标题/hook/封面/脚本组合。
10. 用户导出 Markdown / JSON。
11. 用户发布后手动回填数据。
12. 系统展示表现最好的版本特征。

## 7. 功能需求

### Must Have

#### 7.1 新建项目

字段：

- 项目名称
- 平台：先固定小红书
- 模板：xiaohongshu_product_seed
- 视频时长：默认 45 秒
- 商品标题
- 商品链接
- 商品价格
- 商品卖点
- 目标人群
- 素材路径或图片 URL

#### 7.2 生成商品分析

输出：

- 核心卖点
- 功能卖点
- 情绪卖点
- 场景卖点
- 人群痛点
- 信任补强点
- 风险表达

#### 7.3 生成标题和封面文案

输出：

- 至少 5 个标题
- 至少 3 个封面文案

标题类型：

- 痛点型
- 种草型
- 避坑型
- 对比型
- 低价好物型

#### 7.4 生成脚本

至少输出 3 个脚本版本：

- 痛点解决版
- 闺蜜种草版
- 测评对比版

每个脚本包含：

- hook
- 正文
- CTA
- 配音文本
- 字幕文本

#### 7.5 生成分镜

每个分镜包含：

- 镜头编号
- 起止时间
- 画面描述
- 配音
- 字幕
- 素材类型
- 素材提示
- 镜头目的

#### 7.6 生成素材计划

输出：

- 已有素材建议
- 缺失素材
- 建议补拍素材
- 可用替代素材

#### 7.7 生成发布文案

输出：

- 小红书正文
- 标签
- 评论区引导

#### 7.8 批量变体

输出至少 10 个变体。

每个变体包含：

- variant_id
- 标题
- 封面文案
- hook
- 脚本类型
- CTA
- 发布正文

#### 7.9 导出发布包

支持：

- Markdown
- JSON

#### 7.10 手动数据回填

字段：

- 播放量
- 点赞
- 收藏
- 评论
- 完播率
- 备注

### Should Have

- 本地保存项目。
- 项目列表。
- 复制按钮。
- 简单 QA 检查。
- 版本对比表。

### Could Have

- Edge TTS。
- SRT 字幕。
- FFmpeg 成片。
- 自动读取商品图片。
- 自动分析参考爆款视频。

## 8. 用户故事

1. 作为小红书运营者，我想输入商品卖点后自动得到 5 个标题，这样我可以快速测试不同角度。

2. 作为小商家，我想得到完整脚本和分镜，这样我知道该拍什么、怎么剪。

3. 作为矩阵号运营者，我想一次生成 10 个版本，这样我可以分发到不同账号测试。

4. 作为运营负责人，我想记录每个版本的表现，这样我知道哪个 hook 和标题更有效。

5. 作为不懂剪辑的商家，我想先导出发布包，而不是被迫生成完整视频，这样我可以交给剪辑或自己用剪映处理。

## 9. 验收标准

### 9.1 项目创建

- 用户可以通过 API 或 Web 表单创建项目。
- 项目有唯一 ID。
- 项目数据可以被读取。

### 9.2 发布包生成

给定商品：宠物自动饮水机。

输入：

```json
{
  "title": "宠物自动饮水机",
  "price": "89",
  "selling_points": ["静音", "过滤", "可拆洗"],
  "target_audience": "养猫新手"
}
```

系统必须输出：

- 至少 5 个标题
- 至少 3 个封面文案
- 至少 3 个脚本
- 至少 1 个分镜表
- 至少 1 个素材计划
- 至少 1 个小红书发布正文

### 9.3 变体生成

- 一个项目可以生成至少 10 个变体。
- 每个变体有唯一 ID。
- 变体之间标题、hook 或脚本结构至少有一项不同。

### 9.4 导出

- 可以导出 Markdown。
- 可以导出 JSON。
- 导出内容包含标题、脚本、分镜、素材计划、发布文案和变体。

### 9.5 测试数据

- 可以为每个变体手动录入播放、点赞、收藏、评论、完播率。
- 可以按播放或完播率排序。

## 14. 风险

1. AI 文案像广告，缺少真实感。
   - 解决：模板里强制小红书口吻、真实体验、避开硬广。

2. 生成太泛，商家不能直接用。
   - 解决：输入字段增加场景、目标人群、竞品差异、真实体验。

3. 用户更想要成片，不想要发布包。
   - 解决：MVP 验证后快速接 Edge TTS + FFmpeg。

4. 平台数据回填麻烦。
   - 解决：早期手动，后续 CSV 导入或浏览器插件。

5. 模板太少。
   - 解决：先把一个模板做深，再扩展餐饮、招聘、课程、房产。

## 15. 第一轮上线标准

可以说 MVP 完成，当满足：

1. 浏览器或 API 可创建商品项目。
2. 一个商品可生成完整小红书发布包。
3. 一个商品可生成 10 个变体。
4. 可以导出 Markdown / JSON。
5. 可以手动录入每个变体数据。
6. 用 3 个测试商品验证通过：
   - 宠物饮水机
   - 桌面收纳盒
   - 女生通勤包

## 16. 首批商业验证

找 5 个真实用户：

- 2 个电商商家
- 1 个本地生活商家
- 1 个矩阵号运营者
- 1 个知识付费团队

每个用户：

- 选 3 个商品/选题。
- 每个生成 10 个版本。
- 总共每人 30 个发布包。

验证问题：

- 是否比人工快？
- 是否愿意发布？
- 哪个模块最有价值？
- 愿意为脚本包、成片、还是数据看板付费？
- 是否愿意每月订阅？

## 17. Batch 视频工厂升级要求

本 PRD 的 MVP 从“单商品小红书发布包”升级为“批量短视频工厂”时，必须遵守 `docs/PRODUCT_TARGET_BATCH_VIDEO_FACTORY.md`。

### 17.1 升级后的核心用户故事

1. 作为矩阵号运营者，我想一次提交 3-20 个商品，这样我可以批量生成本周内容候选。
2. 作为运营人员，我想每个商品自动生成 Markdown 发布包，这样我可以直接审核标题、脚本、分镜、素材计划和发布文案。
3. 作为内容负责人，我想看到 batch report，这样我能知道哪些商品生成成功、文件在哪里、下一步该补什么素材。
4. 作为投放/运营人员，我想同一商品生成小红书和抖音两种平台风格，这样我可以避免同质化文案跨平台硬发。
5. 作为系统维护者，我想 workflow、agentkit、tools、exporter 都有中文文档，这样后续可以接 tRPC-Agent-Go、Ollama、OpenMontage 和更多模板。

### 17.2 Batch MVP 必须输出

每个 batch：

- `batch_report.md`
- `batch_report.json`
- 每个商品的 project id
- 每个商品的成功 / 失败状态
- 每个商品的发布包路径
- 下一步运营建议

每个商品项目：

- 商品分析
- 内容角度
- 标题候选
- 封面文案
- 三个脚本版本
- 分镜表
- 素材计划
- 配音文案
- 字幕文本
- 发布正文和标签
- 10 个 A/B 变体
- QA 结果
- 人工审核 checklist

### 17.3 Batch MVP 验收标准

1. `smoke/batch_products_request.json` 至少包含 3 个商品。
2. `POST /api/v1/batches/run` 能同步跑完 render=false 主路径。
3. 生成的 Markdown 对运营人员可读，不只是 JSON dump。
4. 小红书 / 抖音输出在标题、hook、CTA、caption、分镜节奏上有明显差异。
5. 无 API key 时仍能完成发布包和 report。
6. 所有新增模块有中文 doc 和测试说明。
