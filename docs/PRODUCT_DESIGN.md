# 产品设计：本地 Agentic 短视频生产 + 批量测试系统

## 1. 产品一句话

面向小红书 / 抖音 / 视频号矩阵运营者和小商家的本地 AI 短视频生产后台：输入商品、素材和卖点，自动生成符合平台风格的脚本、分镜、素材计划、配音字幕、发布包和 5-10 个 A/B 测试版本。

## 2. 产品定位

本产品不是一个单点“视频生成器”，也不是传统剪辑软件，而是一个面向商业短视频生产的 Agentic workflow system。

核心定位：

```text
输入素材和卖点 -> 平台模板 -> Agent 工作流 -> 人工审核 -> 发布包/成片 -> 批量变体 -> 数据回流
```

产品要解决的是“持续稳定地产出可发布、可测试、可复用的短视频内容”，而不是一次性生成一个炫技视频。

## 3. 代表项目分析

### 3.1 OpenMontage

链接：https://github.com/calesthio/OpenMontage

定位：开源 agentic video production system。

可借鉴：

- Pipeline-driven production，不是单点工具。
- 从需求到脚本、素材、配音、字幕、剪辑、验证、最终合成。
- 每个视频请求先选 pipeline，再执行阶段。
- 强调工具能力探测、交付承诺和质检。

本项目差异：

- OpenMontage 偏通用视频生产。
- 本项目垂直面向小红书 / 抖音 / 视频号 / 电商矩阵。
- 本项目更强调模板化、批量变体和测试数据回流。

### 3.2 OpenCut

链接：https://github.com/OpenCut-app/OpenCut

定位：免费开源视频编辑器，面向 web、desktop、mobile。README 中提到未来有 Editor API、plugin-first architecture、MCP server、headless mode、scripting tab。

可借鉴：

- Headless mode：未来可作为批量渲染/剪辑能力参考。
- Editor API：适合把自动生成的分镜和素材变成可编辑项目。
- Plugin-first architecture：方便后续接平台模板、字幕样式、素材工具。
- MCP server：适合让 Agent 控制剪辑器。

本项目差异：

- OpenCut 是剪辑器。
- 本项目不是先做剪辑器，而是做生产后台和工作流。
- 剪辑器能力可以后续作为渲染/编辑层接入，不作为 MVP 核心。

### 3.3 Voicebox

链接：https://github.com/jamiepine/voicebox

定位：local-first AI voice studio，支持本地语音克隆、TTS、语音输入、Agent voice output、API/MCP。

可借鉴：

- Local-first voice stack。
- 多 TTS 引擎。
- 语音 profile / persona。
- API-first + MCP，可被 Agent 调用。
- 长文本自动分块和音频后处理。

本项目差异：

- Voicebox 是语音工作室。
- 本项目只需要视频生产链路中的 voiceover 子系统。
- MVP 先用 Edge TTS，后续再接 Voicebox 类能力实现品牌音色和多人声。

### 3.4 MoneyPrinterTurbo

链接：https://github.com/harry0703/MoneyPrinterTurbo

定位：输入主题或关键词，自动生成视频文案、素材、字幕、背景音乐并合成短视频。

可借鉴：

- 从主题到短视频的自动化链路。
- Web UI + API UI。
- 短视频生成的一站式体验。
- 面向普通用户的低门槛使用方式。

本项目差异：

- MoneyPrinterTurbo 更像“自动生成一条视频”。
- 本项目更强调平台风格、垂直行业模板、人工审核、批量变体和 A/B 测试。
- 本项目的核心商业价值是“持续内容生产和测试”，不是单条视频自动生成。

## 4. 目标用户

### 4.1 第一优先级：小红书 / 抖音矩阵号运营者

特征：

- 手里有多个账号。
- 每天需要大量标题、脚本、封面、素材组合。
- 不是缺一个视频，而是缺持续生产和测试能力。

核心痛点：

- 写脚本慢。
- 同质化严重。
- 不知道哪个 hook、标题、封面好。
- 内容排期和版本管理混乱。

### 4.2 第二优先级：本地生活商家

包括餐饮、探店、美业、健身、家政、民宿等。

核心痛点：

- 不会持续做内容。
- 没有专业剪辑和运营。
- 需要大量“店铺活动 / 产品 / 案例 / 用户反馈”短视频。

### 4.3 第三优先级：跨境电商卖家

核心痛点：

- 同一个商品要多平台、多语言、多角度测试。
- 商品素材很多，但短视频生产效率低。
- 不知道哪些卖点适合不同平台。

### 4.4 第四优先级：知识付费团队 / MCN 小团队

核心痛点：

- 课程和直播内容需要切片和改写。
- 批量生成标题、封面、脚本、口播稿。
- 需要标准化生产流程，而不是每条都从零开始。

## 5. 核心痛点

现有工具的问题：

1. 剪辑工具偏编辑
   - 适合已经有脚本和素材的人。
   - 不能解决选题、脚本、分镜、发布包和批量测试。

2. AI 生成工具偏单点
   - 只能生成文案、图片、视频片段或配音。
   - 缺少完整生产流水线。

3. 平台适配弱
   - 小红书、抖音、视频号风格差异很大。
   - 通用脚本很难直接发布。

4. 缺少批量测试
   - 短视频真正要测标题、封面、hook、脚本结构。
   - 大部分工具不记录版本和表现数据。

5. 小团队没有标准生产后台
   - 素材、脚本、版本、数据都分散在表格、飞书、剪映和聊天记录里。

## 6. 产品形态

### 6.1 垂直行业模板库

模板不是简单 prompt，而是一套 workflow：

```text
输入字段 -> 内容角度 -> 脚本结构 -> 分镜规则 -> 素材规则 -> 字幕风格 -> 发布文案 -> QA 规则 -> 变体规则
```

首批模板建议：

1. 小红书商品种草
2. 抖音商品强钩子带货
3. 视频号生活化推荐
4. 餐饮探店
5. 房产带看
6. 招聘岗位介绍
7. 课程/知识短视频
8. 跨境商品 TikTok 风格，后续

### 6.2 AI 视频生产后台

用户输入：

- 商品 / 服务 / 课程信息
- 素材
- 卖点
- 目标人群
- 平台
- 风格
- 时长

系统输出：

- 标题
- 封面文案
- 脚本
- 分镜
- 素材需求
- 配音文案
- 字幕
- 发布正文
- 标签
- 成片或半成品发布包

### 6.3 短视频 A/B 测试助手

核心价值：同一个商品/选题生成多个版本，并记录表现。

跟踪维度：

- 标题
- 封面文案
- 开头 hook
- 脚本结构
- 卖点顺序
- 配音风格
- 字幕样式
- 发布时间
- 平台

数据指标：

- 播放量
- 点赞
- 评论
- 收藏
- 转发
- 完播率
- 线索/成交备注

## 7. MVP 范围

### 7.1 MVP 只做一个核心场景

建议 MVP：

```text
手动商品信息 / 1688 商品信息 -> 小红书种草视频发布包 -> 10 个测试变体
```

先不做：

- 自动抓淘宝/1688 页面，先手动输入或复制字段。
- 多平台全覆盖，先小红书。
- 全自动成片，先发布包和素材计划。
- 自动平台发布，先人工复制发布。
- 自动抓平台数据，先手动回填。

### 7.2 MVP 必须有的东西

1. 商品项目
   - 商品标题
   - 链接
   - 价格
   - 卖点
   - 图片/素材
   - 目标人群

2. 小红书种草模板
   - 标题生成
   - 封面文案
   - 脚本
   - 分镜
   - 素材计划
   - 发布正文
   - 标签

3. 人工编辑
   - 脚本可编辑
   - 分镜可编辑
   - 标题/封面可编辑

4. 变体生成
   - 至少 5 个版本，目标 10 个版本。
   - 每个版本要有唯一编号。

5. 发布包导出
   - Markdown
   - JSON
   - 复制到剪映/小红书的文本

6. 测试数据回填
   - 手动填播放量、点赞、收藏、评论、完播率。

## 8. 用户流程

### 8.1 新建项目

用户打开本地网页：

```text
http://127.0.0.1:8088
```

点击“新建视频项目”。

填写：

- 商品名
- 商品链接
- 平台：小红书
- 模板：商品种草
- 目标人群
- 卖点
- 素材目录
- 视频时长

### 8.2 生成发布包

系统运行 Agent workflow：

```text
ProductAnalyzer -> AnglePlanner -> ScriptWriter -> Director -> MaterialPlanner -> QAReviewer -> ExportPackager
```

输出发布包。

### 8.3 人工审核

用户逐步确认：

- 卖点是否准确
- 标题是否可用
- 脚本是否像人话
- 分镜是否能拍/能剪
- 素材是否够
- 发布文案是否符合平台

### 8.4 批量生成变体

用户点击“生成 10 个测试版本”。

系统按不同变量生成：

- 标题变体
- Hook 变体
- 封面文案变体
- 脚本结构变体
- CTA 变体

### 8.5 发布和回填数据

用户人工发布后，把数据填回来：

- 播放
- 点赞
- 收藏
- 评论
- 完播率
- 备注

系统展示哪类版本表现好。

## 10. 指标体系

### 10.1 激活指标

- 创建第一个项目
- 生成第一个发布包
- 导出第一个 Markdown / JSON
- 生成第一个变体组

### 10.2 质量指标

- 发布包可用率：用户认为“稍微改改就能发”的比例。
- 脚本重写率：用户需要大改的比例。
- QA 通过率：禁用词、时长、素材缺失检查通过比例。

### 10.3 效率指标

- 从商品输入到第一版发布包的时间。
- 单商品生成 10 个版本所需时间。
- 人工从零写 10 条 vs 系统生成 10 条的节省时间。

### 10.4 业务指标

- 每周项目数
- 每周变体数
- 每个用户导出次数
- 付费意愿
- 每条发布包愿意支付价格

### 10.5 内容效果指标

- 播放量
- 完播率
- 点赞率
- 收藏率
- 评论率
- 私信/线索/成交备注

## 12. 竞争策略

不要和剪映、OpenCut 直接比剪辑能力。

不要和通用 AI 视频工具比生成效果。

要打的差异点：

1. 平台化
   - 小红书 / 抖音 / 视频号风格模板。

2. 工作流
   - 从商品输入到发布包，不是单个工具。

3. 批量测试
   - 一次生成多个版本，记录数据。

4. 本地化
   - 本地素材、本地模型、本地数据。

5. 可控
   - AI 生成 + 人工审核，而不是盲目全自动。

## 13. 第一轮验证实验

### 实验：5 个商家批量生产试点

假设：

小商家愿意使用“AI 发布包 + 人工修改”的方式，把单商品 10 条内容的生产时间降低 70%。

目标用户：

- 2 个小红书商品商家
- 1 个本地生活商家
- 1 个跨境电商卖家
- 1 个知识付费团队

执行：

- 每个用户选 3 个商品/选题。
- 每个商品生成 10 个发布包。
- 总计 150 条发布包。
- 用户人工挑选并发布其中一部分。

成功标准：

- 60% 以上发布包被认为“可用或稍改可用”。
- 单商品 10 个版本生成时间小于 15 分钟。
- 至少 2 个用户愿意为下一批内容付费。
- 用户明确指出最有价值模块：脚本、标题、分镜、素材计划、成片或数据看板。

决策：

- 如果脚本/标题价值最高，先强化模板和 LLM。
- 如果素材计划价值最高，优先做素材库。
- 如果成片需求最高，优先做 FFmpeg 渲染。
- 如果测试数据价值最高，优先做 A/B 看板。

1. 第一目标用户：小红书 / 抖音矩阵运营者和小商家。
2. 第一模板：小红书商品种草。
3. 第一输出：发布包，不是完整成片。

5. 第一技术策略：本地 deterministic workflow，后接 tRPC-Agent-Go 和本地 LLM。
